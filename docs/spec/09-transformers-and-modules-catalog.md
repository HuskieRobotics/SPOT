# 09 — Transformers and Modules Catalog

## Transformer framework

- **TR-1** `class DataTransformer { constructor(name, execFunc); execute(dataset, outputPath, options) }`
  — `execute` simply calls `execFunc`. (The comment about making existing paths read-only is
  not implemented.)
- **TR-2** Transformer files live in `src/analysis/transformers/`. A file may contain one
  `__TMP__ … __/TMP__` block and one `__TEAM__ … __/TEAM__` block, each holding exactly one
  `new DataTransformer("<fileName>", fn)` expression **without** a trailing semicolon. The
  bundle route wraps them as `{ tmp: { name: <expr>, … }, team: { … } }` inside an async
  `getTransformers()` that first fetches `match-scouting.json` and computes `actionIds`
  (unique button ids across all layers, first-appearance order). `getPath`, `setPath`, and
  `matchScoutingConfig` are available to transformer code as globals from the template scope.
- **TR-3** Helper semantics: `getPath(obj, "a.b.c", ifnone)` throws if the path is missing and
  no default is given; `setPath` creates intermediate objects.
- **TR-4** `tmp` transformers iterate `dataset.tmps`; `team` transformers iterate
  `Object.entries(dataset.teams)` and select `dataset.tmps.filter(t => t.robotNumber == team)`.

Transformer authoring rules (from CONTRIBUTING and TRANSFORMERS_README): document options with
JSDoc, keep one transformer per type per file, never delete or modify existing dataset paths,
handle divide-by-zero and missing data, avoid game terminology, and put any code outside the
`new DataTransformer(...)` expression into the template file rather than the transformer file.

## Module framework

- **MO-1** A module is a class with `constructor(moduleConfig)` creating `this.container`
  (`div.container.<kind>`), `formatData(teams: string[], dataset) → data` (may be async), and
  `setData(data)` (may be async). `moduleConfig` is the entry from `analysis-modules.json`.
- **MO-2** Modules are discovered from `src/analysis/modules/<Name>/index.js` and
  `style.css`; the class name must equal the folder name.
- **MO-3** Common option conventions: `path` (team path), `aggrMethod: "sum"` (else average
  across the given teams), `multiplier`, `addend`, `decimals`, `unit`, `hideIfValue`,
  `sort` (1 = higher is better, -1 = lower is better, 0/undefined = no rank).
- **MO-4** Rank badges: when `sort` is set and a single team is displayed, the team's rank
  among all teams with a valid value is computed; CSS classes `top5` (≤ 5 %), `top25`, `top50`,
  else `top100`.
- **MO-5** Plotly modules call `getCssVar` for theme colors, use font Cairo, title size 32,
  `responsive: true`, and remove the zoom/pan mode-bar buttons.
